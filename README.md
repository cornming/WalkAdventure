# 走走冒險 WalkAdventure 2.0

「你走的每一步，都是全家的冒險與回憶。」

這是一款以 Android 真實計步感測器（`TYPE_STEP_COUNTER`）驅動的**純本機離線親子實境冒險 RPG**：兼顧「平日大人日常累積」與「假日／晚間親子共玩」，把日常走路轉化為營火開箱、孵蛋與 3 階段旅伴進化、秘密營地建設、奇幻小菜園澆水、多話連貫繪本故事與線下親子抬頭任務。

## 遊戲特色與系統

### 1. 雙軌親子節奏（平日蓄積 × 假日共玩）
- **頂部一鍵切換「平日模式／親子出任務」**：大人通勤走路時，步數寶箱與撿到的神祕蛋可自動鎖存進「**營火盒**」，留到晚上或假日和孩子一起點燃營火開箱並享受親子加成。
- **本機家庭小隊護照（1～6 人、免帳號）**：同一台手機可建立大人與孩子的小隊卡（暱稱、角色、選填生日），勾選今日出隊成員；壽星生日當天營地還會掛上彩旗並送出生日禮包。
- **口袋探險模式（走路不低頭）**：出門點一下「🎒 口袋」，收進口袋安心牽手散步，抵達休息點再一鍵揭曉收穫。

### 2. 探險分頁（活著的世界 × 連貫故事 × 守護巨獸 × 抬頭任務）
- **真實時段與四季聯動**：依手機真實時間與月份動態變換清晨／正午／黃昏／星夜天空漸層、四季漂浮粒子與台灣節慶驚喜（100% 離線）。
- **五大主題島嶼 × 島嶼守護巨獸試煉**：每章 8 格探索路徑，可透過「累計步數」或「完成 1 張親子抬頭任務」二選一安撫守護巨獸、領取稀有神祕蛋。
- **10 條連貫繪本故事（共 30 話）＋ 經典雙選項奇遇**：每 500 步觸發一次奇遇，讀完 3 話故事線還會解鎖故事徽章與神祕蛋。
- **24 張分齡線下「親子抬頭任務卡」**：涵蓋觀察、動作與對話引導（支援學齡前／中高年級／全齡篩選），完成時可順手寫下孩子的一句童言童語收進手札留念。

### 3. 營地分頁（互動秘密營地 × 孵蛋巢 × 奇幻小菜園）
- **可點擊繪本營地畫布（CC0 繪本素材）**：直接點擊畫布上的營火開箱、蛋巢暖蛋／破殼、花圃播種採收，或摸摸在草地散步的旅伴賺取每日羈絆。
- **6 座營地建設（Lv.0 → Lv.5）**：營火廣場、奇幻小菜園、旅伴樂園、星光觀景台、回憶畫廊小屋與探險工坊，提供長尾金幣與星砂成長目標。
- **走路澆水奇幻菜園（3 格花圃）**：金幣購買向日葵、星星莓、彩虹蘿蔔種子，日常步數自動澆水成熟，採收旅伴點心、星砂與稀有花瓣蛋。
- **孵蛋巢與 12 位旅伴（3 階段進化＋閃亮異色＋飾品）**：保留原本 4 位元老旅伴並擴充至 12 位；走路推進孵蛋＋每日「親子暖蛋」加速，餵食點心可由幼年進化至成長與大師形態，並可於探險工坊製作草帽、紅圍巾與星光王冠穿戴。

### 4. 相機尋寶與實境冒險明信片（Phase 2 新增・100% 離線隱私保護）
- **12 題實境相機尋寶（彩虹七色＋5 項親子自然觀察）**：免申請 `CAMERA` 權限直接呼叫系統相機拍照（或從相簿挑剛拍的照片），本機即時以 **HSV 色彩分析引擎**偵測主色調並由大人與孩子共同打星（1～3★）。集滿現實世界紅、橙、黃、綠、藍、紫、白七色可解鎖**彩虹七色大獎與花瓣奇蹟蛋**。
- **繪本風《實境冒險明信片》合成與分享**：用 Android Canvas 合成 `1080×1440` 高解析明信片，整合實景照片、**孩子的手指塗鴉圖層**、進化後旅伴插畫、當日步數郵戳、彩虹鑑定章與出隊小隊印章，可一鍵分享到家庭群組或保存收藏。
- **15 秒親子語音便條 × 回憶時光機**：可在明信片錄下孩子的童言童語（僅錄音時動態申請麥克風權限，全存於 App 本機私有目錄絕不上傳雲端），並在手札頁的「回憶時光機」自動回顧去年的今天與過往珍藏。

### 5. 手札與小隊分頁（圖鑑 × 四季護照 × 24 項成就 × 離線備份）
- **手札分頁**：彩虹七色現實世界收集冊、回憶時光機、實境冒險明信片牆、12 位旅伴圖鑑、10 條連貫繪本故事冊與親子抬頭任務回憶留念卡。
- **小隊分頁**：家庭小隊護照管理、近 7 天步數長條圖與戰報複製、每日步數任務、四季印章護照（每季 8 枚）、24 項成就稱號、冒險日誌，以及一鍵複製／貼上還原本機 2.0 備份 JSON。
- **100% 舊存檔向下相容與元老禮遇**：從 `v0.1.0–v0.5.0` 覆蓋安裝升級時，原有真實步數、金幣、裝備、旅伴與營地全數無痛保留；硬體計步基準仍隔離於 `walk_adventure_device`，並保留 GitHub Releases SHA-256 驗證自動更新。

### 6. 繪本新手引導與流暢慶祝動畫
- **4 頁互動繪本導覽 × 分頁情境小幫手 × 隨時可開說明手冊**：首次開啟自動帶領認識平日／親子雙模式、營地互動、相機明信片與口袋模式；4 個分頁皆附可關閉的首次造訪提示卡，點擊頂部「❓」可隨時翻閱 8 項玩法指南或重播導覽。
- **流暢 30–60fps 繪本畫布與全螢幕慶祝動畫**：探險與營地畫布具備連續飄落四季粒子、太陽／星光呼吸脈動、營火火星上升、待破殼神祕蛋俏皮搖晃、摸摸旅伴冒出愛心與對話泡泡，以及營火開箱、孵蛋破殼、進化升級、收成與明信片完成時的穿透式彩帶粒子慶祝動畫（自動尊重 Android 系統「移除動畫」無障礙設定）。

### 步數怎麼算

手機的計步感測器回報的是「開機以來的累計步數」，App 每次讀到新的數字，就把和上一次讀數的差額加進進度。規則寫在 [`StepProgress.java`](app/src/main/java/com/cornming/walkadventure/StepProgress.java)，2.0 遊戲系統與序列化寫在 [`AdventureState.java`](app/src/main/java/com/cornming/walkadventure/AdventureState.java)、[`CompanionSystem.java`](app/src/main/java/com/cornming/walkadventure/CompanionSystem.java)、[`CampState.java`](app/src/main/java/com/cornming/walkadventure/CampState.java)、[`StoryCatalog.java`](app/src/main/java/com/cornming/walkadventure/StoryCatalog.java) 與 [`SaveCodec.java`](app/src/main/java/com/cornming/walkadventure/SaveCodec.java)：

- **App 沒開也算**：關著 App 走的步數，下次打開時會一次補進累積步數；期間跨過的每一個 1000 步寶箱都會補發。
- **今日步數**：每天歸零，從當天第一次讀到感測器（通常是當天第一次打開 App）之後開始算。在那之前走的步數分不出是哪一天的，只算進累積步數。
- **重開機**：感測器會從 0 重新累計，App 會用開機次數分辨，重開機之後走的步數照樣計入，今日步數不會歸零。
- 安裝後第一次讀到感測器時只記下起點，安裝前走的步數不算。
- 裝備、奇遇與每日任務給的是「冒險 XP」與金幣獎勵，不會改動「今日真實步數」與「累計真實步數」。

## 下載、安裝與更新

### 首次安裝
1. 到本 repo 的 [Releases](../../releases) 頁面，下載最新版的 `WalkAdventure-vX.Y.Z.apk`。
2. 在 Android 手機上開啟 APK，依系統提示允許「安裝未知應用程式」。
3. 第一次執行時允許「活動辨識」權限（計步需要）；若曾永久拒絕權限，可點一下主畫面直接前往系統設定開啟。

### App 內自動檢查與下載更新
- App 啟動時會於背景自動查詢最新 Release（約每 3 小時檢查一次，或點擊畫面底部「檢查更新」按鈕手動檢查），發現新版本時會自動下載並驗證 SHA-256 與檔案大小。
- 新版 APK 驗證就緒後，畫面會提示可「立即安裝」（亦可隨時點底部綠色按鈕安裝）；首次在 App 內更新時依系統提示開啟「允許來自此來源的應用程式」後返回即可繼續覆蓋安裝，原本的步數、金幣與冒險進度都會保留。（受限於 Android 系統安全規範，最後仍需由使用者在系統安裝畫面確認「更新」。）
- `INTERNET` 與 `REQUEST_INSTALL_PACKAGES` 權限僅用於檢查與安裝本倉庫 Releases 更新；其餘計步與遊戲資料完全離線運作。

> **舊版 APK 簽章不同，第一次換新版需先解除安裝舊版，本機存檔會消失。**
> 這只會發生一次；從固定簽章的版本開始，之後都可以直接覆蓋安裝。

每個版本的更新內容會整理在該版 Release 說明中。

## 建置與 CI

GitHub Actions 使用 Gradle 8.10 與 Android Gradle Plugin 8.6.1 建置 APK（JDK 17）：
- **PR 驗證**（[`.github/workflows/ci.yml`](.github/workflows/ci.yml)）：Pull Request 會自動檢查 shell 腳本語法、執行單元測試、Android Lint 與 `assembleDebug`。
- **自動發佈**（[`.github/workflows/release.yml`](.github/workflows/release.yml)）：推上 `main` 時計算版號，通過單元測試與 Lint 後自動建置 debug APK 並發佈 GitHub Release；若標籤已存在會直接跳過建置，只改 Markdown 檔不會觸發。

本機建置（需要 JDK 17、Android SDK 與 Gradle 8.10）：

```bash
gradle testDebugUnitTest   # 計步規則的單元測試
gradle lintDebug           # Android Lint 檢查
gradle assembleDebug
```

APK：`app/build/outputs/apk/debug/app-debug.apk`

本機建置沒有設定環境變數時，versionCode 為 `1`、versionName 為 `0.1.0`。

## 版號規則

- **versionName**：由 [`.github/scripts/next-version.sh`](.github/scripts/next-version.sh) 依「上一個版本標籤（`vX.Y.Z`）之後的提交訊息」計算，採用 [Conventional Commits](https://www.conventionalcommits.org/zh-hant/) 格式：

  | 提交內容 | 版號變化 | 範例 |
  | --- | --- | --- |
  | 類型帶 `!`，或內文有 `BREAKING CHANGE` | 主版號 +1（次版號、修訂號歸零） | `feat!: 重做存檔格式` |
  | `feat` | 次版號 +1（修訂號歸零） | `feat: 新增地圖` |
  | 其他（`fix`、`docs`、`chore`⋯⋯） | 修訂號 +1 | `fix: 修正計步重複計算` |

  上一個標籤之後有多筆提交時，取最高的一項。repo 還沒有任何版本標籤時，第一版為 `0.1.0`。
- **versionCode**：使用 GitHub Actions 的 run number，只增不減。Android 不允許用 versionCode 較低的 APK 覆蓋較高的版本，所以新版 versionCode 一定要比舊版大。
- **Release 說明**：由 [`.github/scripts/release-notes.sh`](.github/scripts/release-notes.sh) 把上一個標籤之後的提交，依破壞性變更／feat／fix／其他分組整理，開頭附安裝方式與覆蓋安裝說明。

## 簽章

debug 建置使用 repo 內固定的金鑰 `keystore/debug.keystore`（別名 `androiddebugkey`，密碼 `android`），由 `app/build.gradle` 的 `signingConfigs.debug` 指定。這樣 CI 每次建置的簽章都相同，新版才能直接覆蓋安裝。

這把金鑰是公開的，只適合 debug／個人使用，不可用於正式上架。原因與安全性取捨請見 [`keystore/README.md`](keystore/README.md)。
